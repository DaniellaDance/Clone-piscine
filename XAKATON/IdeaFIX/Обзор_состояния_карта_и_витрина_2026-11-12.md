# IdeaFix: текущее состояние карты вендоров и витрины идей

Дата обзора: 12 ноября 2026.
Папка проекта: `XAKATON/IdeaFIX`.
Характер документа: только описание текущего состояния. Код не изменялся, ничего не публиковалось, `git status` чистый.

---

## 1. Проект в двух словах

IdeaFix 2.0 — MVP системы обратной связи сотрудников ГК «Модус Трейд»: Node.js (`server.mjs`), PostgreSQL (Neon, схема `ideafix`), статические клиенты в `public/` (сайт, телефон, ПК, установка), PWA.

Обе рассматриваемые части — клиентский слой поверх двух источников данных:

- файл `catalog.json` — справочник вендоров, отраслевых и технических решений, продуктов и услуг;
- таблицы `ideafix.*` — обращения, голоса, проекты Казахстана, постоянные клиенты, уточнённые отраслевые связи вендоров.

## 2. Карта вендоров

### 2.1. Где находится

Страница «Мои партнёры» (`page = 'ecosystem'`), первая из трёх вкладок:

- «🌍 Карта мира» (`selectPartnerTab('map')`);
- «Компании» — алфавитный список, группировка по стране / техническому / отраслевому решению;
- «★ Постоянные клиенты».

Реализация: `showPartnerWorldMap()` в `public/assets/catalog-ui.js`, монтируется в контейнер `#partner-world-map`, панель деталей — `#partner-map-details`.

### 2.2. Как устроена

Собственный рендерер карты, без Leaflet / MapLibre / внешних библиотек:

- растровые тайлы `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, сетка 256 px, добирается по видимой области;
- проекция Меркатора считается вручную (`merc` / `unmerc`), долгота корректируется на перенос через −180/180;
- перетаскивание — pointer-события (`pointerdown` / `pointermove` / `pointerup` / `pointercancel`), центр ограничен по широте ±80°;
- зум — колесо мыши и кнопки «＋» / «－», диапазон 2…8, кнопка «Весь мир» возвращает zoom 2 и центр `[25,55]`;
- переключатель «Маршруты»;
- стартовый центр задан как `[25,55]`; в коде он трактуется как lat 25° / lng 55°, но при zoom 2 обзор почти мировой, и Омск с Астаной попадают в кадр.

Политика безопасности сервера это разрешает: в `server.mjs` (строка 46) в `Content-Security-Policy` указано `img-src 'self' data: https://tile.openstreetmap.org`. Без этой строки тайлы блокировались бы браузером.

### 2.3. Что показывается

| Объект | Вид | Источник | Действие по клику |
|---|---|---|---|
| Страны присутствия вендоров | 🔵 точка | `countryMapPoints` в `catalog-ui.js`, 18 стран | список вендоров страны → карточка вендора |
| Головной офис, Омск | ★ | константа `omsk` | описание офиса, ссылка на modus-trade.ru |
| Модус Трейд Казахстан, Астана | ◆ | константа `astana` | описание, mail@modus-trade.kz, ссылка на modus-trade.kz |
| Реализованные проекты Казахстана | 📍 по городам, группируются | `GET /api/completed-kz-projects` (таблица `ideafix.completed_kz_projects`) | список проектов города, вендор, ссылка на modus-trade.kz/projects |
| Постоянные клиенты | только список, без точек | `GET /api/regular-clients` | — (координат в справочнике нет, это прямо сказано в интерфейсе) |
| Маршруты | пунктирные SVG-кривые | — | Омск → страны (кроме России), Астана → города проектов |

Иконка проекта выбирается по названию: «Туркестан» → 🏟️, «Hilton» → 🏨, «Аэропорт» → ✈️, иначе 🎓; несколько проектов в городе — 🏙️ со счётчиком.

Клик по стране открывает список компаний этой страны; каждая ведёт в карточку вендора (`openVendorCard`): часы вендора с разницей во времени, панель «✉️ Написать вендору» (mailto, выбор отправителя), схема «Модус Трейд → вендор → компетенции» и рабочее место вендора — связанные проекты/пилоты, ближайшие встречи, идеи и обращения.

### 2.4. Данные карты

`catalog.json` (проверено 11.11.2026, источник `https://modus-trade.kz/brands/`):

- 41 вендор, идентификаторы `v1…v41`;
- 19 кодов стран: AT 3, CA 1, JP 1, RU 15, US 3, GB 1, CZ 2, IT 2, NL 1, PL 1, DE 3, FR 1, AU 1, UNCONFIRMED 1, CN 1, KR 1, IL 1, CH 1, FI 1;
- ATS помечен `UNCONFIRMED`, координат для него нет — на карте достижимы 40 вендоров из 41;
- 11 отраслевых решений (бизнес-центр, медицина, аэропорт, нефтедобыча, безопасный город, граница, ЖД вокзал, банк, спортивный объект, гостиница, музеи);
- 19 технических решений (видеонаблюдение, СКУД, пожарная и охранная сигнализация, оповещение, пожаротушение, громкоговорящая связь, противотаранные устройства, интеграционная платформа, сетевое оборудование, термошкафы, взрывозащищённое оборудование, кондиционирование, охранное освещение, палатная связь, кабельные системы, ИТ, транспортный досмотр, радарная охрана периметра);
- 69 продуктов и услуг, у каждого вендора есть хотя бы одно направление;
- у 32 вендоров есть логотип, у 29 — email, у 35 — телефон;
- подтверждённые отраслевые связи по умолчанию только у 3 вендоров; остальные 38 попадают в группу «Отрасли требуют уточнения».

Дополнительно карта опирается на таблицы `ideafix.completed_kz_projects` и `ideafix.regular_clients` (`schema.sql`, строки 102 и 104).

### 2.5. Что заметно в текущем состоянии (не исправлялось)

1. **Нет атрибуции OpenStreetMap.** На карте отсутствует обязательная подпись «© OpenStreetMap contributors» — это требование tile usage policy OSM. Тайлы при этом запрашиваются прямо с `tile.openstreetmap.org` из браузера, без прокси и собственного кэша.
2. **Проекты Казахстана только читаются.** Для `ideafix.completed_kz_projects` в API есть лишь `GET`; интерфейса добавления нет. На чистой базе карта покажет вендоров, Омск и Астану, но ни одной точки проекта.
3. **Клиентов добавить можно, увидеть на карте — нет.** Постоянные клиенты создаются через форму, но координат в справочнике нет, поэтому они выводятся только списком. Это честно объяснено в интерфейсе, но выглядит как незавершённая часть.
4. **Точки стран, а не адреса.** Одна точка на страну (например, все 15 российских вендоров — одна метка в районе 94° в.д., 61° с.ш.), маршруты условные и не отражают фактическую логистику. В подписи карты это оговорено.
5. **Доступность.** Панорамирование только мышью и пальцем: клавиатурного управления картой нет, кнопки зума и пины имеют `aria-label`, но сам регион карты не описывает управление.
6. **Пустое состояние.** При ошибке загрузки проектов панель пишет «Проекты временно не загружены. Карта вендоров доступна.», а при пустом массиве просто нет пинов, без пояснения.
7. **«Схема холдинга» — это не карта.** В README она описана отдельно; в коде это блок `ecosystemGraph()` внутри карточки вендора (Modus → вендор → компетенции), а не географическая карта.

## 3. Витрина идей

### 3.1. Два представления

1. **Панель на «Главной»** — `renderHomeShowcase()`, `public/assets/app.js` (строка 254). Правая колонка-«витрина», добавляется только когда `page === 'feed'`:
   - 6 идей, отсортированных по голосам, затем по дате создания;
   - периоды День / Неделя / Месяц / Квартал / Все (по умолчанию «Месяц»);
   - кнопка «⛶ На весь экран» (`home-showcase-fullscreen`, на узких экранах скрыта);
   - кнопка «Открыть ↗» — переход на страницу витрины.
2. **Страница «Витрина идей»** — `page = 'ideas'`, рендер `renderList()` (строка 264), карточки `showcaseTile` (строка 253):
   - заголовок «Витрина идей» и подпись «Идеи сотрудников, открытые для обсуждения и поддержки»;
   - те же пять периодов;
   - сетка стеклянных карточек: метка «ИДЕЯ» или «ДЕМО», тематическая иконка, заголовок, краткое описание, «👍 голоса» и текущий статус;
   - счётчик найденных идей рядом с поиском; пагинации на этой странице нет — выводится весь отфильтрованный список.

### 3.2. Логика отбора и голосования

- Отбор: `kind === 'idea'` **и** `published` **и** попадание в выбранный период (`showcaseDateMatch` по полю `created`).
- Сортировка: по числу голосов (`votes`), при равенстве — по дате создания (новые выше).
- Публикация: только через `PATCH /api/tickets/:id` пользователем с правами управления (`director`, `admin`, `lead` своего отдела). Сервер разрешает флаг `published` только для `kind === 'idea'` и неанонимных обращений (`server.mjs`, строка 165).
- Голос: `POST /api/tickets/:id/vote`, только за опубликованную идею; первичный ключ `(ticket, voter)` в `ideafix.votes` даёт один голос на сотрудника. Отмены голоса нет.
- Видимость: опубликованные обращения видны всем авторизованным, но полный текст сервер отдаёт только автору, получателю и руководителю — остальным в ответе подставляется заголовок (`server.mjs`, строка 140).

### 3.3. Что заметно в текущем состоянии (не исправлялось)

1. **Период считается по дате создания, а не публикации.** Отдельного `published_at` в схеме нет, поэтому идея, созданная в прошлом месяце и опубликованная сегодня, не попадёт в фильтр «День».
2. **Дублирование текста в карточке.** Из-за подстановки заголовка вместо тела (пункт выше) у чужих идей краткое описание под заголовком повторяет сам заголовок.
3. **Демо-набор не наполняет витрину.** `demo.mjs` вставляет 4 обращения, но без `published`, поэтому после «Добавить ДЕМО» витрина остаётся пустой, пока руководитель не опубликует идею.
4. **Неиспользуемый ассет.** В `public/assets/` лежит `Витрина идей на фоне гор.png` (около 2,1 МБ); ни один файл её не подключает, в репозитории она остаётся.
5. **Расхождение с концепцией.** `CONCEPT.md` обещает «идею дня», недельный шортлист, «идею месяца от директора» и склейку похожих обращений. В коде есть только фильтры периода и голосование; механик «идея дня / недели / месяца» и объединения похожих нет.
6. **Дрейф документации.** README говорит о 14 технических решениях, в `catalog.json` их 19. Про отраслевые связи README точен: подтверждены лишь у части вендоров, остальные собраны в отдельную группу, а дополняются директором через `PUT /api/vendor-scopes`.

## 4. Как витрина связана с картой вендоров

- В обращении хранятся `vendor_id`, `industry_id`, `technical_id`, `offering_id` / `offering_name`; они показываются бейджами в карточке обращения (витрина, лента, отчёты).
- Сервер проверяет совместимость: техническое решение должно входить в компетенции выбранного вендора, продукт — принадлежать этому вендору и соответствовать решению (`catalog-rules.mjs`).
- Отрасль выбирается независимо от вендора; подтверждённые связи хранятся в `ideafix.vendor_scopes` и подмешиваются на клиент при загрузке страницы.
- Карточка вендора подтягивает связанные идеи, пилоты и встречи через `GET /api/vendors/:id/workspace` с ролевой фильтрацией (`vendor-workspace.mjs`): директор и администратор видят всё, руководитель — свой отдел, сотрудник — свои и опубликованные.
- Географических координат у вендора нет: на карте вендор представлен точкой страны из захардкоженного справочника координат.

## 6. Итог

- **Карта вендоров** — рабочая кастомная карта мира на тайлах OSM с точками стран, офисами Омск/Астана, проектами Казахстана, маршрутами и переходом в карточки вендоров. Главные пробелы: нет атрибуции OSM, проекты нельзя добавлять из интерфейса, на пустой базе карта без проектов.
- **Витрина идей** — два представления (панель на главной и отдельная страница), пять периодов, голосование с одним голосом на сотрудника, публикация только руководителем. Главные пробелы: период по дате создания, дублирование текста у чужих идей, демо-набор не публикуется, обещанные концепцией «идея дня/недели/месяца» не реализованы.
