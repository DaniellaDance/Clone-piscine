# IdeaFIX 2.0

Рабочий MVP системы обратной связи сотрудников ГК «Модус Трейд».

## Возможности
- Регистрация сотрудника, вход, сессии на 30 дней в HttpOnly cookie.
- Серверное разграничение прав: сотрудник, руководитель отдела, директор, администратор.
- Обращения, категории по правилам, приоритет, сроки первого ответа, комментарии и история.
- Анонимные обращения: автор не сохраняется, отслеживание по номеру и случайному коду.
- Витрина идей после публикации руководителем, уникальный голос сотрудника, день / неделя / месяц.
- Пульс компании, нагрузка отделов, просрочки, результаты, экспорт CSV.
- Общая PostgreSQL база Neon: синхронизация устройств каждые 15 секунд.
- Адаптивный сайт и устанавливаемое PWA для Android, iOS и компьютеров.

## Запуск
Node.js 22+, PostgreSQL.

```sh
npm ci
npm run build
DATABASE_URL='postgresql://...' DIRECTOR_PASSWORD='...' npm start
```

`DIRECTOR_PASSWORD` задаётся секретной переменной только при создании аккаунта `director`. Пароль не хранится в исходниках. Новые сотрудники регистрируются самостоятельно; руководителей назначает директор в «Управлении».

Исходники клиентов — `public/`. Сайт: `/`, телефон: `/mobile.html`, ПК: `/desktop.html`, установка: `/install.html`. Миграция `schema.sql` создаёт собственную схему `ideafix`, не меняя чужих таблиц. `npm test` запускает интеграционный тест с реальной тестовой базой и удаляет только созданные им записи. На Render проверка выполняется перед публикацией.

## Границы MVP
Классификация и похожие идеи работают по правилам, языковая модель не подключена. Уведомления — внутри открытого приложения; почта, push, 1С и Битрикс24 не подключены. Просрочки отображаются в сводке; автоматическая внешняя эскалация не настроена. PWA требует интернет для входа и работы с обращениями; офлайн кэширует только оболочку. Отдельные APK / EXE и магазинные релизы не созданы. Electron-папка — исходный вариант оболочки, рекомендуемый способ установки — PWA. Для корпоративной эксплуатации требуются SSO и согласование политики доступа, резервирования и обработки данных.

## Опубликованная версия
Сайт: https://br-wandering-hat-b9hqnoxc-ideafixapp.compute.c-7.eu-central-1.aws.neon.tech/

Мобильное приложение: `/mobile.html`, ПК: `/desktop.html`, установка: `/install.html`.

Из-за исчерпанных минут сборки Render публикация выполнена на Neon Functions. `index.mjs` — серверный адаптер; `function-adapter.mjs` переводит web Request/Response в единый обработчик. Архив содержит сервер, `public/`, `schema.sql` и production-зависимости. Для Functions задать `NEON_FUNCTION=1`, `NODE_ENV=production` и секрет `DIRECTOR_PASSWORD`; `DATABASE_URL` предоставляет платформа. `RUN_VERIFICATION=1` запускает проверки на реальной базе при загрузке новой функции; тестовые записи удаляются. Проверки успешно пройдены 10 ноября 2026 года.

Render-сервис `ideafix-modus` сохранён, но не работает до восстановления минут сборки. Основной рабочий адрес — Neon Functions. GitHub не публикует изменения в Neon Functions автоматически: после изменений нужно повторно собрать и загрузить архив.

## Девять этапов улучшения
В карточке обращения доступен маршрут: Инсайт → Предложение → Регистрация → Обсуждение → Оценка → Решение → Пилот → Внедрение → Результат. При подаче сообщения фиксируются инсайт и предложение, обращение получает этап «Регистрация». Руководитель уточняет данные и последовательно ведёт карточку; сотрудник видит прогресс и результаты.

Для оценки фиксируются затраты, эффект и реализуемость. Решение — принять, доработать или отклонить с обоснованием. Пилот требует принятого решения, плана, ответственного и срока; внедрение — результата пилота; завершение — описания внедрения, показателей до/после и итога. Каждый переход сохраняется в истории. Перепрыгивание этапов и изменение этапов сотрудником блокируются сервером. Проверки полного маршрута и ограничений пройдены на реальной базе.
