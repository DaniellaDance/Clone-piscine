# FIX Idea 2.0

Рабочий MVP системы обратной связи сотрудников ГК «Модус Трейд».

## Возможности
- Регистрация сотрудника, вход, сессии на 30 дней в HttpOnly cookie.
- Серверное разграничение прав: сотрудник, руководитель отдела, директор, администратор.
- Обращения, категории по правилам, приоритет, сроки первого ответа, комментарии и история.
- Анонимные обращения: автор не сохраняется, отслеживание по номеру и случайному коду.
- Витрина идей после публикации руководителем, уникальный голос сотрудника, день / неделя / месяц.
- Пульс компании, нагрузка отделов, просрочки, результаты, экспорт CSV.
- Общая PostgreSQL база Neon: синхронизация устройств каждые 15 секунд.
- Адаптивный сайт и устанавливаемое PWA для Android, iOS и компьютеров.

## Запуск
Node.js 22+, PostgreSQL.

```sh
npm ci
npm run build
DATABASE_URL='postgresql://...' DIRECTOR_PASSWORD='...' npm start
```

`DIRECTOR_PASSWORD` задаётся секретной переменной только при создании аккаунта `director`. Пароль не хранится в исходниках. Новые сотрудники регистрируются самостоятельно; руководителей назначает директор в «Управлении».

Исходники клиентов — `public/`. Сайт: `/`, телефон: `/mobile.html`, ПК: `/desktop.html`, установка: `/install.html`. Миграция `schema.sql` создаёт собственную схему `ideafix`, не меняя чужих таблиц. `npm test` запускает интеграционный тест с реальной тестовой базой и удаляет только созданные им записи. На Render проверка выполняется перед публикацией.

## Границы MVP
Классификация и похожие идеи работают по правилам. ИИ-помощник имеет бесплатный режим по правилам: он работает без ключей, кредитов и интернета и всегда доступен. Freebuff и Gemini подключаются как необязательные внешние провайдеры; при их отсутствии, ошибке или исчерпанном лимите помощник отвечает в бесплатном режиме и помечает результат как `free_mode`. Статус провайдеров: `GET /api/ai/status`. Уведомления — внутри открытого приложения; почта, push, 1С и Битрикс24 не подключены. Просрочки отображаются в сводке; автоматическая внешняя эскалация не настроена. PWA требует интернет для входа и работы с обращениями; офлайн кэширует только оболочку. Отдельные APK / EXE и магазинные релизы не созданы. Electron-папка — исходный вариант оболочки, рекомендуемый способ установки — PWA. Для корпоративной эксплуатации требуются SSO и согласование политики доступа, резервирования и обработки данных.

## Опубликованная версия
Сайт: https://br-wandering-hat-b9hqnoxc-ideafixapp.compute.c-7.eu-central-1.aws.neon.tech/

Мобильное приложение: `/mobile.html`, ПК: `/desktop.html`, установка: `/install.html`.

Из-за исчерпанных минут сборки Render публикация выполнена на Neon Functions. `index.mjs` — серверный адаптер; `function-adapter.mjs` переводит web Request/Response в единый обработчик. Архив содержит сервер, `public/`, `schema.sql` и production-зависимости. Для Functions задать `NEON_FUNCTION=1`, `NODE_ENV=production` и секрет `DIRECTOR_PASSWORD`; `DATABASE_URL` предоставляет платформа. `RUN_VERIFICATION=1` запускает проверки на реальной базе при загрузке новой функции; тестовые записи удаляются. Проверки успешно пройдены 10 ноября 2026 года.

Render-сервис `ideafix-modus` сохранён, но не работает до восстановления минут сборки. Основной рабочий адрес — Neon Functions. GitHub не публикует изменения в Neon Functions автоматически: после изменений нужно повторно собрать и загрузить архив.

## Девять этапов улучшения
В карточке обращения доступен маршрут: Инсайт → Предложение → Регистрация → Обсуждение → Оценка → Решение → Пилот → Внедрение → Результат. При подаче сообщения фиксируются инсайт и предложение, обращение получает этап «Регистрация». Руководитель уточняет данные и последовательно ведёт карточку; сотрудник видит прогресс и результаты.

Для оценки фиксируются затраты, эффект и реализуемость. Решение — принять, доработать или отклонить с обоснованием. Пилот требует принятого решения, плана, ответственного и срока; внедрение — результата пилота; завершение — описания внедрения, показателей до/после и итога. Каждый переход сохраняется в истории. Перепрыгивание этапов и изменение этапов сотрудником блокируются сервером. Проверки полного маршрута и ограничений пройдены на реальной базе.

## Один экран
Рабочее пространство занимает высоту окна (`100dvh`), страница не прокручивается целиком. На телефоне навигация перестраивается, в горизонтальном виде — уходит в боковую колонку. Карточка разделена на вкладки «Обращение», «Этапы», «История»; форма показывает только поля выбранного этапа и сохраняет остальные значения. Список обращений имеет постраничное переключение. Если текста много или экран очень мал, прокручивается содержимое панели внутри границ экрана. Инструкция установки открывается внутри рабочего пространства.

Отправка в Битрикс ограничена сохранённой стадией `proposal` («Предложение»): сервер отклоняет другие этапы с 409 и пользователей без прав с 403. Кнопка видна только на этом этапе, пока отключена: подключение Битрикс24 отсутствует, запрос на допустимом этапе возвращает 503 и ничего не отправляет.

При создании можно выбрать тип «Инсайт / Заявка / Предложение» и связать запись с вендором и решениями. Сервер проверяет идентификаторы; выбранные области сохраняются в PostgreSQL, отображаются в карточке и отчёте CSV.

Вкладка «Контакты вендоров» содержит страны, компетенции, официальные страницы контактов, доступные email/телефоны и источники. Страна компании/владельца марки отделена от места производства. У 40 записей указана страна (18 стран). Для Smartec Россия указана по самоописанию марки на официальном сайте, а не как универсальная страна владельца и производства. ATS требует уточнения: официально подтверждён адрес оператора Advisor Advanced Pro в Нидерландах, что не определяет страну изготовления устройств. Не следует выводить страну всех изделий из адреса регионального дистрибьютора. Актуальность: 11.11.2026.

«Схема холдинга» — интерактивная партнёрская экосистема Modus → вендор → компетенции. Стрелки не означают владение вендорами со стороны Modus. Связи брендов Sentinel/Complitech и Заря/Пунктир-А/ТвинПро указаны отдельно.

Карта мира работает на собственных тайлах OpenStreetMap с обязательной ссылкой «© OpenStreetMap contributors». Проекты Казахстана добавляются прямо с карты кнопкой «＋ Проект» (директор и администратор) и проверяются по координатам в пределах страны; постоянные клиенты с координатами отмечаются звёздочкой. Карта управляется мышью, пальцем и клавиатурой (стрелки, плюс и минус).

RU / EN / KZ переключает интерфейс, формы, этапы, справочник и сообщения системы; выбор хранится на устройстве. Казахский язык имеет стандартный код `kk`, кнопка — `KZ`. Ввод пользователя, названия компаний и комментарии не подвергаются машинному переводу. Открытые формы сохраняют свои значения при переключении. Файлы `catalog-ui.js`, `translations.js`, `i18n.js` используются всеми тремя клиентскими страницами. Интеграция с Битрикс24 по-прежнему требует подключения.

### Дизайн и цитата дня

Стиль «Траектория идеи»: светлый фон, графит, кобальт и оранжевый акцент, горная иллюстрация и векторный знак IF. Manrope и Noto Sans хранятся локально; казахский интерфейс использует Noto Sans. Лицензии OFL находятся рядом со шрифтами.

На главной после входа вместо заголовка «От инсайта до результата» показывается цитата дня с автором и ссылкой на первоисточник. Банк содержит 7 цитат, цикл повторяется раз в неделю. Смена — в полночь Asia/Almaty, одинаково для всех пользователей; открытая вкладка обновляет цитату в течение 30 секунд или при возвращении на страницу. RU и KK — редакционные переводы английского оригинала. Проверка: `node --test daily-quotes.test.mjs`.

### Задачи в Битрикс24

Портал: https://b24-hdamjr.bitrix24.kz. Директор подключает входящий вебхук в «Управление → Подключить Битрикс24». Нужны права `task` и `user` (либо совместимый доступ к `user.get`), доступ к REST API и право постановщика назначать задачи выбранным сотрудникам. Вебхук хранится в отдельной серверной таблице, не возвращается API и не включается в исходники. При подключении проверяются `user.get` и `tasks.task.getFields`; реальные задачи проверка подключения не создаёт.

На сохранённой стадии «Предложение» автор или руководитель выбирает активного сотрудника из справочника портала и нажимает «Отправить предложение в битрикс». Сервер вызывает `tasks.task.add`, передавая его ID как `RESPONSIBLE_ID`: задача появляется в «Моих задачах» именно исполнителя. Постановщик — владелец вебхука. В задачу передаются предложение, польза, отправитель и отдел; внутренние комментарии и анонимные коды не передаются. В ответ возвращается ссылка на созданную задачу. Дедупликация по паре предложение/исполнитель предотвращает повторную постановку, включая неясный результат после тайм-аута: в таком случае сначала требуется сверка с порталом. Ошибки обязательных пользовательских полей задач возвращаются как отказ отправки.

Автотесты без реальных отправок: `node --test bitrix.test.mjs daily-quotes.test.mjs`. Без входящего вебхука интеграция остаётся неподключённой, задачи не создаются.



## Обновление 11 ноября: голос, руководители и совещания

Результат редактируется и подтверждается автором до отправки. При отказе микрофона/сети сохраняется уже распознанный текст. Для KK доступно оформление без орфографической проверки; семантическая ИИ-редактура не подключена. Аудио приложение не сохраняет. Поддержка диктовки зависит от браузера.
- «Отделы и сотрудники» строится по аккаунтам; выбранный личный получатель получает доступ к обращению. Роли и подразделения назначает директор.
- Директор может добавить помеченный набор «ДЕМО»: 7 руководителей, 7 сотрудников, 4 обращения, 2 встречи. Вымышленные аккаунты не имеют общего пароля. Повторное добавление набора не создаёт дубликаты.
- Календарь совещаний и форумов: месяц и ближайшие, время Казахстана UTC+5. Руководители добавляют доступные обращения в повестку. «Подготовить речь» собирает сохранённые сведения повестки и, по выбору, новые обращения; это редактируемый шаблон выступления, а не генерация языковой моделью. Печать поддерживает сохранение в PDF средствами браузера.
- «Пилоты» показывает текущий этап pilot, план, владельца и срок. При сохранении пилота задача автоматически отправляется в настроенный проект Bitrix24 «Пилотные проекты». Настройка требует входящего вебхука с task, user, sonet и выбора проекта/исполнителя. Без подключения пилот остаётся в IdeaFix с объяснением. Повтор/неясный результат не создаёт дубликат; неизвестные результаты требуют сверки.
- «Чат руководителей» доступен только director и lead. Сохраняется в PostgreSQL, опрашивается открытым приложением каждые 5 секунд. Фоновых web-push нет.
- В «Управлении» директор подключает закрытые чаты только директора и всех руководителей. Telegram/MAX/WhatsApp получают сообщения чата; Bitrix24 — только срочные сообщения директора, плюс системные уведомления явно выбранным руководителям. Для Bitrix это маркировка СРОЧНО и уведомления, не недокументированный системный раздел «Важное». Секреты не возвращаются клиенту. Отображение «принято сервисом» не означает прочтение людьми. При сетевой неопределённости автоматического повтора нет.
- Telegram: бот в закрытой группе, токен и chat_id. После проверки названия чата директор подтверждает подключение. Кнопка демо отправляет ровно одно сообщение в Telegram, с идемпотентным ключом; другим каналам этот тест не пересылается. MAX: официальный Bot API platform-api2.max.ru. WhatsApp: требуется официальный Groups API и доступный бизнес-аккаунт, обычная ссылка на группу недостаточна. Каналы по умолчанию выключены. Токены вводятся в защищённую форму, не в исходники.
- Технические решения ограничиваются компетенциями выбранного вендора (включая дополнительные компетенции справочника); несовместимые сочетания отвергает сервер. Привязки отраслей заполняются директором с основанием в «Настроить отрасли вендоров». Общая лента логотипов на отраслевых страницах не использована как доказательство: до подтверждения отрасль для такого вендора не предлагается.

Проверки: `node --test bitrix.test.mjs proofread.test.mjs`. Новые таблицы добавляются schema.sql без удаления существующих данных. Публикация на Neon Functions выполняется отдельно от GitHub. Внешняя доставка требует настроенных ключей и проверяется отдельно; отсутствие подключения не считается успешной доставкой.


### Push-уведомления
Системные Web Push для личных обращений и срочных сообщений директора. Пользователь включает подписку через 🔔 и разрешает уведомления браузера. Ключи VAPID хранятся в серверном окружении PUSH_VAPID_PUBLIC / PUSH_VAPID_PRIVATE, закрытый ключ в GitHub не попадает. Подписки привязаны к аккаунту; при выходе отписываются. Текст баннера не раскрывает содержимое обращения. Показываются в свёрнутом приложении, если ОС и браузер разрешают фоновую доставку; нельзя гарантировать баннер поверх абсолютно всех окон. Кнопка теста отправляет уведомление только текущему пользователю. Закрытый браузер, ограничения фоновой работы, настройки уведомлений и DND могут задерживать/скрывать баннеры.


### План дня
Личный план с выбором даты, временем и длительностью задач, пятью демо-примерами. Рабочие задачи при создании передаются в Bitrix24 назначенному владельцу через подтверждённое соответствие аккаунтов; личные остаются локально. Без подключения рабочие задачи ожидают передачи. Неопределённый результат не повторяется автоматически во избежание дублей. Импорт Google Календаря выполняется из файла .ics с предварительным просмотром; постоянная синхронизация Google не подключена.



### Fathom: реальные встречи
В календаре совещаний кнопка «Fathom · итоги встреч» открывает личный импорт руководителя. Settings → API Access → Generate API key → Manage → Add Webhook: вставьте Destination URL из FixIdea, выберите my_recordings, Summary и Transcript. Секрет подписи whsec_… сохраните только в защищённой форме приложения; API key не нужен. Подключение не считается проверенным до получения настоящего подписанного события. Отключение прекращает приём, сохраняя уже полученные материалы.

Запись запускается в Fathom, а не внутри FixIdea. После окончания и обработки вебхук сохраняет итоги и расшифровку отдельно от медиа. Текст речи загружается только по кнопке. Free не гарантирует автоматические action items: Premium-функции не активируются, внешние платные модели не вызываются. Полученные задачи можно отредактировать и сохранить в свой план дня; идеи — в свой отдел с отдельным флажком публикации на витрине. Без выбора публикации идея закрыта. Ответственные и сроки не угадываются. Печать итогов/PDF использует браузер.

Подпись: HMAC-SHA256 по исходному телу, constant-time comparison, окно 5 минут. Повторные события обновляют одну запись по owner + recording_id. При сохранении результатов используются транзакция и блокировка записи для защиты от повторного клика. Импорт не отправляет сообщения или задачи в Bitrix. Каждый аккаунт видит только свои записи, включая директора. Для совместного доступа потребуется отдельная явная настройка.

Проверка: `node --test fathom.test.mjs`. Документация: https://developers.fathom.ai/webhooks и https://developers.fathom.ai/api-reference/webhook-payloads/new-meeting-content-ready .


### Итоги совещаний и встреч
Отдельная вкладка руководителей показывает материалы Fathom, обновляется каждые 15 секунд, пока открыта. После подписанного события запись сопоставляется с расписанием: уникальная ссылка + время (±10 минут), иначе точная тема с нормализацией регистра/пробелов + время. Несколько совпадений или отсутствие даты не дают автоматической привязки: владелец выбирает встречу вручную. При привязке материалы доступны руководителям отдела встречи и директору, исходная неподключённая запись остаётся личной.

Рядом со строкой встречи появляется «📎 Итоги». Постоянные ссылки позволяют скачать TXT с полной расшифровкой, кратким описанием и идеями/предложениями. Файлы строятся из сохранённого текста, не обращаясь к аудио Fathom. Есть печать/PDF итогов и полной расшифровки; удаление записи в Fathom не удаляет сохранённые материалы FixIdea. Идеи — дословные выдержки из разделов идей/предложений кратких итогов или явных предложений в речи, а не полноценный семантический ИИ-анализ. Пустой результат честно обозначен. Добавление идеи и публикация на витрине выполняются пользователем.

Готовые аудио/видеофайлы не принимаются Fathom. Их импорт и распознавание требуют отдельного обработчика и пока не подключены.

После получения непустых итогов и расшифровки в каждом просмотре записи отображается предложение удалить медиа в Fathom. Ссылка открывает исходную запись; удаление вручную подтверждает владелец в Fathom. FixIdea не сообщает об успешном удалении, поскольку API Fathom не позволяет удалять записи. Текстовые материалы FixIdea сохраняются независимо.


### Доступ по отделам и порядок переписки
Директор/администратор видит заявки всех отделов. Руководитель видит записи, проекты, пилоты, обсуждения и материалы встреч своего отдела. Обычный сотрудник видит собственные/адресованные ему обращения и неанонимные идеи, проекты и пилоты своего отдела, но не текст/анализ встреч и не рабочий чат руководителей. Сервер проверяет доступ к карточкам, вложениям, скачиваниям, ИИ-анализу и Битрикс-отправкам; публикация чужой идеи и знание ID не обходят отдел.

Сотрудник может адресовать обращение своему руководителю или сотруднику своего отдела. Руководитель — своим сотрудникам и директору. Директор — всем. Это применяется к текстовым и медиаобращениям, а также к выбору исполнителя Битрикс (для недиректорских ролей требуется проверенная локальная привязка аккаунта). Если руководитель отправляет директору, заявка остаётся в отделе отправителя.

Чат руководителей разделён по отделам. Директор выбирает отдел для отправки; все отделы доступны ему в режиме чтения. Старая общая переписка без отдела доступна только директору. Внешние общие группы не получают новую закрытую переписку отдела: у них нет подтверждённого состава получателей по отделам. Уведомления срочного сообщения адресуются только директору и руководителям соответствующего отдела. Неопределённые по отделу записи календаря и карты доступны только руководству.

### Собственные идеи директора
Настройки личного кабинета → «Кому показывать мои собственные идеи»: Только я / Только руководители / Все сотрудники. По умолчанию «Только я». Изменение применяется ко всем неанонимным идеям данного автора, включая ранее созданные; другие идеи и материалы встреч не изменяются. Это явное разрешение автора на показ его собственных идей между отделами. Видимость проверяется независимо от published и прямого получателя, в том числе на карточках и вложениях. Перенос идеи из совещания сохраняет ссылку на номер источника, а не публичную внешнюю ссылку на всю запись.

### Демо-финансы
Результаты → «Показать демо-базу»: 4 проекта и 4 пилота в KZT, включая прибыль, убыток и нулевой результат. Вымышленные записи хранятся в отдельной demo_project_finances, имеют устойчивые ключи, не дублируются при перезапуске и не смешиваются с реальными суммами. Доступ — директору. Общий импорт финансов из Битрикса доступен директору: его записи пока не имеют проверенной классификации по отделам.

Проверки: `node --test *.test.mjs` (интеграционный тест пропускается без TEST_DATABASE_URL). Изменения схемы и SQL видимости проверены на отдельной ветке Neon; TEST_DATABASE_URL должен указывать только на изолированную тестовую ветку.
