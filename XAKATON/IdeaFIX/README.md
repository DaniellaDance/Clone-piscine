# IdeaFix

Система обратной связи и предложений сотрудников для ГК «Модус Трейд».
Проект собран к хакатону: работающий прототип на трёх платформах — сайт, мобильное приложение и приложение для ПК.

## Что внутри

| Файл / папка | Что это |
|---|---|
| `index.html` | Сайт (веб-версия). Полный функционал: лента, карточка обращения, дашборд директора, голосование, администрирование |
| `mobile.html` | Мобильное приложение (PWA). Подача обращения в одно поле, лента, голосование, «Мои обращения» |
| `desktop.html` | Приложение для ПК: окно с меню и рабочей областью — как обычная программа, без браузера |
| `desktop-app/` | Обёртка Electron: `npm install && npm start` — IdeaFix запускается отдельным окном на Windows, macOS и Linux |
| `assets/seed.js` | Демонстрационные данные: 20 обращений из датасета хакатона |
| `assets/app.js` | Логика веб-версии |
| `assets/mobile.js` | Логика мобильной версии |
| `assets/styles.css` | Дизайн-система (общая для всех версий) |
| `assets/mobile.css` | Мобильные стили |
| `manifest.webmanifest` | Установка мобильной версии на телефон как приложение |
| `CONCEPT.md` | Продуктовая и техническая концепция для защиты |

## Как запустить

Сайт, мобильная версия и ПК-оболочка — обычные файлы, сборка не нужна. Достаточно поднять локальный сервер в папке проекта:

```bash
cd IdeaFix
python3 -m http.server 3000
```

Дальше:

- сайт — http://localhost:3000/index.html
- мобильная версия — http://localhost:3000/mobile.html (в браузере включите режим телефона)
- ПК-приложение — http://localhost:3000/desktop.html

ПК-приложение как отдельная программа:

```bash
cd IdeaFix/desktop-app
npm install
npm start
```

Все три версии используют одну и ту же демо-базу в браузере, поэтому обращение, поданное с телефона, сразу появляется на сайте и в ПК-приложении.

## Что показывать на демо (4 минуты)

1. **Сотрудник.** На телефоне: «Подать» → текст про нехватку полей в заявках на оборудование. Помощник сам определяет категорию и ответственного, обращение регистрируется за 15 секунд.
2. **Дубликаты.** Если текст похож на существующее обращение, система предлагает поддержать его вместо создания нового. Похожие жалобы склеиваются в одну тему с общим числом голосов.
3. **Руководитель.** На сайте переключите роль на «Руководитель»: виден таймер до ответа, просрочка подсвечивается красным, статус меняется в карточке, комментарий фиксирует решение.
4. **Автор.** Возвращается в «Мои обращения» и видит не «в работе», а конкретный результат.
5. **Директор.** Роль «Директор» → «Пульс компании»: где болит сильнее всего, нагрузка по подразделениям, просрочки, что уже реализовано. Все обращения видны целиком.
6. **Голосование.** «Идеи» → «День / Неделя / Месяц»: голос за лучшую идею. Победа даёт приоритет в рассмотрении, а не только грамоту.

## Роли

Переключатель роли — в верхней панели сайта и по нажатию на имя роли в мобильной версии:

- **Сотрудник** — подаёт обращения, следит за своими, голосует.
- **Руководитель** — ведёт обращения своего направления: статусы, ответственные, внутренние комментарии.
- **Директор** — видит все обращения без исключения, дашборд, берёт темы на контроль.
- **Администратор** — правила маршрутизации, нормативы сроков, права доступа, анонимные обращения.

## Данные

Демонстрационные, из датасета хакатона: 20 обращений, 18 категорий, 7 подразделений. Все имена и ситуации вымышлены. Данные хранятся в браузере (localStorage), поэтому перезагрузка страницы их не стирает. Кнопка сброса не нужна: чтобы вернуть исходный набор, очистите данные сайта в браузере.

## Ограничения демо

- Нет сервера и базы: данные живут в браузере. Для пилота нужен backend — он описан в `CONCEPT.md`.
- Интеграции с Битрикс24 и 1С показаны как концепция, живого обмена нет.
- AI-помощник в демо — прозрачные правила по ключевым словам, а не языковая модель. Логика «помощник предлагает, человек решает» сохранена.
- Уведомления показаны всплывающими сообщениями, без почты и мессенджеров.
